The ten loader models

Each one has exactly one job. Nothing for the first 200 ms; spinner to one second; skeleton beyond that; determinate progress past ten seconds with a way out. Never a fake percentage.

1 · Skeleton

first paint

Real row heights and column widths. Varying line widths so it reads as text, not a barcode.

2 · Inline button spinner

user action

Never a full-page overlay for one action.

3 · Top progress bar

route change

Two pixels, pinned below the top bar. Replaces full-page spinners entirely.

4 · Determinate progress

upload · export

4 of 11 photos · 2.1 MB of 5.8 MB

Percentage alone is not context. Always name the unit.

The rules that keep it consistent

Always

Borders separate, shadows elevate. Only popovers, modals, drawers, toasts and sticky bars get a shadow.
Status is glyph plus label. Test it in greyscale.
Every number, VIN and duration in mono with tabular figures.
Tokens only — no raw hex, px or ms in component code.
Sentence case, active voice, verb plus object on every button.

Never

Gradients, glassmorphism, decorative icons, illustrations of people.
ALL-CAPS eyebrow labels, arrows glued to button text, dot-joined meta strings.
Scroll-triggered reveals, staggered list entrances, hover lift on cards.
“Oops”, “Something went wrong!”, or “Saved” when it only saved locally.
A fake percentage, or a loader that can spin forever.

Before opening a pull request, remove one thing from the screen and check whether anyone would miss it. Usually not.
